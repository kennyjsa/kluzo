# v0.1 · Núcleo

**Objetivo:** executar uma milestone do GitHub de ponta a ponta, em sequência, com Claude Code, pela CLI.

**Marco:** o Kluzo passa a orquestrar o próprio desenvolvimento (item 11).

**Fora do escopo:** paralelismo, fila de merge, MCP, OpenCode, GitLab, web e upstream com agentes. O plano é escrito à mão em `.kluzo/plans/` e aprovado pela CLI.

Cada item está no formato de issue: título, features, área, dependências e critérios de aceite.

---

### 1 · Esqueleto do projeto Go
- **Features:** F29
- **Área:** `area/build`
- **Depende de:** —
- **Aceite:**
  - O módulo Go tem `cmd/kluzo` e `internal/`, e a CLI usa Cobra (`kluzo --version`).
  - O CI do repositório roda `go test`, `go vet` e lint em todo PR.
  - O build gera um binário único para Linux e macOS (amd64 e arm64).

### 2 · Configuração `.kluzo/`
- **Features:** F04
- **Área:** `area/config`
- **Depende de:** 1
- **Aceite:**
  - O Kluzo carrega `kluzo.yaml`, `roles/*.md` (frontmatter e prompt) e `flows/*.yaml`.
  - A validação acusa: papel inexistente num flow, par harness + modelo inválido, schema inválido. Cada erro aponta o arquivo e a linha.
  - `kluzo init` gera uma configuração inicial com os papéis e flows padrão.

### 3 · Estado e journal em SQLite
- **Features:** F28, F02
- **Área:** `area/core`
- **Depende de:** 1
- **Aceite:**
  - Modelos de workspace, nó e transição, gravados em SQLite com WAL.
  - Toda transição gera uma entrada no journal, e há um teste por transição válida e inválida.
  - Matar o processo em qualquer ponto e subir de novo não perde nem duplica trabalho.

### 4 · Adaptador GitHub
- **Features:** F23
- **Área:** `area/tracker`
- **Depende de:** 1
- **Aceite:**
  - Lê a milestone, as issues e as dependências `blocked_by`.
  - Aplica as labels `orch/*` e escreve um comentário por transição.
  - Cria branch, abre PR, consulta checks e faz merge.
  - Autentica como GitHub App. Usa polling.

### 5 · Grafo e scheduler sequencial
- **Features:** F10
- **Área:** `area/core`
- **Depende de:** 3, 4
- **Aceite:**
  - Monta o grafo a partir do plano e das issues, só com arestas de bloqueio.
  - Recusa iniciar com ciclos ou com dependências fora da milestone, explicando o motivo.
  - Escolhe o próximo nó pronto pelo caminho crítico. Um nó só fica pronto quando os bloqueios estão integrados.
  - O scheduler não chama LLM.

### 6 · Runtime Claude Code
- **Features:** F24
- **Área:** `area/runtime`
- **Depende de:** 1
- **Aceite:**
  - Implementa o contrato de [interfaces.md](../contracts/interfaces.md) (`Check`, `Start`, `Resume`; `Events`, `Wait`, `Send`, `Cancel`) sobre `claude -p --output-format stream-json`.
  - Os eventos são normalizados e gravados no journal, com custo por sessão.
  - `Cancel` mata o grupo de processos inteiro. A versão mínima da CLI é verificada.

### 7 · Execução de nó
- **Features:** F11
- **Área:** `area/core`
- **Depende de:** 5, 6
- **Aceite:**
  - Cada nó roda num worktree que nasce da ponta da branch da milestone.
  - Executa o `flow node.yaml` (implementer → reviewer), e o reviewer pode devolver o nó com findings.
  - A saída de cada papel é validada pelo schema; saída inválida conta como falha.
  - Um nó interrompido retoma do último papel concluído.

### 8 · Gates
- **Features:** F12
- **Área:** `area/core`
- **Depende de:** 7
- **Aceite:**
  - Executa os gates de `kluzo.yaml`, por comando ou pelos checks do CI.
  - O resultado vem do comando ou do CI, nunca do agente. Gate vermelho volta para o implementer com o log.

### 9 · Branch da milestone e merge
- **Features:** F02, F13 (parcial), F22 (parcial)
- **Área:** `area/scm`
- **Depende de:** 8
- **Aceite:**
  - Cria ou adota `milestone/<nome>`. Depois dos gates verdes, faz o merge do nó nela.
  - Com todos os nós integrados, abre o PR `milestone → main`. O merge na `main` é sempre humano.

### 10 · CLI de operação
- **Features:** F29, F09 (parcial)
- **Área:** `area/cli`
- **Depende de:** 9
- **Aceite:**
  - `kluzo plan`, `approve`, `run`, `status`, `pause`, `resume` e `doctor` funcionam.
  - `approve` faz commit do plano em `.kluzo/plans/<milestone>.yaml`.
  - `doctor` verifica as CLIs, o token do GitHub e a configuração.

### 11 · Dogfooding
- **Features:** —
- **Área:** `area/meta`
- **Depende de:** 10
- **Aceite:**
  - O repositório do Kluzo tem o seu próprio `.kluzo/`.
  - Os itens de [v0.2](v0.2.md) viram issues numa milestone do GitHub, e o Kluzo executa essa milestone.
