# v0.1 · Núcleo

**Objetivo:** executar uma milestone do GitHub de ponta a ponta, em sequência, com Claude Code, pela CLI.

**Marco:** o Kluzo passa a orquestrar o próprio desenvolvimento (item 11).

**Fora do escopo:** paralelismo, fila de merge, MCP, OpenCode, GitLab, web e upstream com agentes. O plano é escrito à mão em `.kluzo/plans/` e aprovado pela CLI.

Cada item está no formato de issue: título, features, área, dependências e critérios de aceite.

**Estado (08/11/2026):** integrados em `milestone/v0.1` os itens 1, 2, 3, 4 e 5. O 6b está em execução; o 6 está liberado (ADR 0024).

### 1 · Esqueleto do projeto Go
- **Features:** F29
- **Área:** `area/build`
- **Depende de:** —
- **Aceite:**
  - O módulo Go tem `cmd/kluzo` e `internal/`, e `kluzo --version` funciona (CLI na biblioteca padrão; o Cobra entra no item 10).
  - O CI do repositório roda `go test`, `go vet` e lint em todo PR.
  - O build gera um binário único para Linux e macOS (amd64 e arm64).

### 2 · Configuração `.kluzo/`
- **Features:** F04
- **Área:** `area/config`
- **Depende de:** 1
- **Aceite:**
  - O Kluzo carrega `kluzo.yaml`, `roles/*.md` (frontmatter e prompt) e `flows/*.yaml`.
  - A validação acusa: papel inexistente num flow, par harness + modelo inválido, schema inválido. Cada erro aponta o arquivo e a linha.
  - `kluzo init` gera uma configuração inicial com os papéis e flows padrão. Os papéis padrão `implementer` e `reviewer` são os textos de [docs/contracts/roles/](../../contracts/roles/) (ADR 0023); os demais seguem como placeholders até as suas versões.
  - `kluzo roles check` valida os papéis contra o protocolo do binário ([prompt.md](../../contracts/prompt.md#segmento-2--papel)).

### 3 · Estado e journal em SQLite
- **Features:** F28, F02
- **Área:** `area/core`
- **Depende de:** 1
- **Aceite:**
  - Modelos de workspace, nó e transição, gravados em SQLite com WAL.
  - Toda transição gera uma entrada no journal, e há um teste por transição válida e inválida.
  - Matar o processo em qualquer ponto e subir de novo não perde nem duplica trabalho.

### 4 · Adaptador GitHub
- **Features:** F23
- **Área:** `area/tracker`
- **Depende de:** 1
- **Aceite:**
  - Lê a milestone, as issues e as dependências `blocked_by`.
  - Aplica as labels `orch/*` e escreve um comentário por transição.
  - Cria branch, abre PR, consulta checks e observa o merge do PR (nenhum port executa merge; o do nó na milestone é local, no item 9).
  - Autentica como GitHub App (`auth.kind: github_app`) ou por token (`auth.kind: token`). Usa polling.
  - Os testes de integração rodam contra um repositório de sandbox, nunca contra o próprio `kennyjsa/kluzo`.

### 5 · Grafo e scheduler sequencial
- **Features:** F10
- **Área:** `area/core`
- **Depende de:** 3, 4
- **Aceite:**
  - Monta o grafo a partir do plano e das issues, só com arestas de bloqueio.
  - Recusa iniciar com ciclos ou com dependências fora da milestone, explicando o motivo.
  - Escolhe o próximo nó pronto pelo caminho crítico. Um nó só fica pronto quando os bloqueios estão integrados.
  - O scheduler não chama LLM.

### 6 · Runtime Claude Code
- **Features:** F24
- **Área:** `area/runtime`
- **Depende de:** 1, 6b (a investigação 3 está concluída: ADR 0024)
- **Aceite:**
  - Implementa o contrato de [interfaces.md](../../contracts/interfaces.md) (`Check`, `Start`, `Resume`; `Events`, `Wait`, `Send`, `Cancel`) com a invocação do ADR 0024.
  - Os eventos são normalizados conforme events.md e gravados no journal, com custo por `modelUsage`; o stream bruto vai para o log depois do redact.
  - Ambiente sintético, arquivos de configuração `0600`, regras do projeto injetadas da ponta da milestone, hook `PreToolUse` HTTP com canário, verificação das ferramentas no `init`.
  - Classificação do resultado, limites de turnos e custo contados no stream, regras de retomada e UUIDv5, como no ADR 0024.
  - `Cancel` mata o grupo de processos inteiro. A versão mínima da CLI é verificada.
  - Fixtures de stream da versão testada, e a lista de verificações empíricas de [claude-code-runtime.md](../../research/claude-code-runtime.md) executada numa máquina autenticada, com o resultado no relatório.

### 6b · Montagem do prompt e MCP mínimo
- **Features:** F11, F25 (parcial)
- **Área:** `area/runtime`
- **Depende de:** 2 (a investigação 2 está concluída: ADR 0023)
- **Aceite:**
  - `internal/prompt` monta os três segmentos de [prompt.md](../../contracts/prompt.md), com envelope e saneamento, limites e manifesto.
  - Golden por papel e por causa; teste de propriedade de que nenhum texto externo fica fora de um envelope.
  - Servidor MCP local só com `kluzo_result`, com token por sessão (ADR 0019).
  - Segmento 3 com critérios numerados (`AC1..n`), seção `Verify` com os comandos dos gates congelados, findings com id e, para o reviewer, `Previous findings`, `Implementer report` envelopado e `Round diff` (ADR 0023).
  - A parte de ferramentas do protocolo é gerada do `mcp:` do papel.
  - Os textos de `implementer` e `reviewer` em [docs/contracts/roles/](../../contracts/roles/) viram os papéis padrão do `kluzo init`.

### 7 · Execução de nó
- **Features:** F11
- **Área:** `area/core`
- **Depende de:** 5, 6
- **Aceite:**
  - Cada nó roda num worktree que nasce da ponta da branch da milestone.
  - Executa o `flow node.yaml` (implementer → reviewer), e o reviewer pode devolver o nó com findings.
  - O veredito do review é derivado pelo `core` (ADR 0023). O `core` atribui os ids de findings e valida a cobertura de `criteria`, `responses` e `previous`; `caminho:linha` citado como evidência precisa existir no worktree.
  - Rodadas esgotadas com `blocking` aberto levam a `blocked` (`triage`); falhas de gate rápido têm contador próprio (`max_retries`).
  - A saída de cada papel é validada pelo schema; saída inválida conta como falha.
  - Um nó interrompido retoma do último papel concluído.

### 8 · Gates e garantias
- **Features:** F12
- **Área:** `area/core`
- **Depende de:** 7
- **Aceite:**
  - Executa os gates de `kluzo.yaml`, por comando ou pelos checks do CI. Os gates `fast` rodam antes do review.
  - O resultado vem do comando ou do CI, nunca do agente. Gate vermelho volta para o implementer com o log.
  - Os gates são lidos da ponta da milestone no despacho; `env_allow` é respeitado (ADR 0020).
  - Uma mudança em `protected_paths`, testes apagados ou desativados viram proposta; supressões novas viram finding `blocking`.
  - `kluzo doctor` e o início de sessão recusam credenciais do host sem `allow_host_credentials`.

### 9 · Branch da milestone e merge
- **Features:** F02, F13 (parcial), F22 (parcial)
- **Área:** `area/scm`
- **Depende de:** 8
- **Aceite:**
  - Cria ou adota `milestone/<nome>`. Depois dos gates verdes, faz o merge do nó nela.
  - Com todos os nós integrados, abre o PR `milestone → main`. O merge na `main` é sempre humano.

### 10 · CLI de operação
- **Features:** F29, F09 (parcial)
- **Área:** `area/cli`
- **Depende de:** 9
- **Aceite:**
  - `kluzo plan`, `approve`, `run`, `status`, `pause`, `resume` e `doctor` funcionam.
  - `approve` faz commit do plano em `.kluzo/plans/<milestone>.yaml`.
  - `doctor` verifica as CLIs, o token do GitHub e a configuração.
